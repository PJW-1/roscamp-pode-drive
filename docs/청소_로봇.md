# 청소 로봇: 커버리지 경로 생성 (계획 4-2, 단계 1)

청소 로봇이 HALL 바닥을 한 바퀴 쓸고 집 자리(P-1)로 돌아오는 경로를 만든다. 코드는
`pc/fleet_core/fleet_core/coverage.py`이고 numpy만 쓴다(ROS 없음). 관제 연결(역할 설정, 배차 제외,
실행부)은 다음 단계다.

## 만드는 방법

1. **청소 격자(2.5 cm).** 칸 중심이 HALL zone 사각형의 합 안에 있어야 바닥이다. 다음 것에서
   (로봇 반지름 0.083 + 여유 0.01) = 0.093 m 안의 칸은 막는다.
   - 지도 경계(벽)
   - HALL이 아닌 모든 구역(도크, 급행, 입구). 도크 출입구는 열지 않는다
   - `keepout_extra`
   - 진열대: `shelves`와 `sim_shelves`의 합집합. 같은 줄을 시뮬과 실물에서 함께 쓴다

   P-1에서 닿지 않는 빈칸은 쓰지 않는다(v7, d2 모두 0칸).
2. **셀 분해(boustrophedon).** y 칸 줄마다 이어진 빈칸 구간을 찾고, 위아래 줄의 구간이 서로
   하나씩만 겹치면 같은 셀로 묶는다. 갈라지거나 합쳐지는 곳에서 새 셀이 시작된다.
3. **줄.** 줄 방향은 x다. 셀의 맨 아래 칸 줄부터 맨 위 칸 줄까지 줄 간격 이하로 고르게 줄을
   고른다. 줄은 격자 칸 줄 위에 놓이므로 실제 간격은 `floor(줄 간격 / 2.5 cm)`칸 이하다
   (0.10 m는 0.10 m, 0.068 m는 0.05 m). 줄은 그 칸 줄의 셀 구간 양 끝 칸 중심을 잇는다.
4. **순서.** 지금 자리에서 격자 최단 거리(8방향)가 가장 가까운 셀의 시작 줄 끝으로 간다. 셀마다
   아래에서 또는 위에서, 동쪽으로 또는 서쪽으로 시작하는 네 가지 중 가장 가까운 것을 고르고,
   셀 안에서는 줄 방향을 번갈아 바꾼다.
5. **줄 사이 이동.** 직선으로 잇지 않는다. 청소 격자 위 A*(8방향, 모서리 자르기 없음)로 칸 경로를
   찾고, 보이는 점끼리 이어 꺾은선으로 줄인다. 이을 때 pode_fsm이 둥글게 바꾼 모양도 빈칸 위인지
   함께 본다. P-1에서 첫 줄로, 마지막 줄에서 P-1로 가는 길도 같다. P-1이 막힌 칸이면 가장 가까운
   빈칸 중심에서 시작하고 결과의 `home.moved_to_nearest_free`를 true로 둔다.
6. **둥근 경로 검사.** pode_fsm은 받은 경로의 모서리를 `turn_radius_m`(0.10 m,
   `pode_fsm/params.py`) 원호로 바꾼다(`geometry.rounded`, 호 점 간격 0.01 m). coverage는 같은
   계산을 따로 둔다(fleet_core는 pode_fsm에 의존하지 않는다). 줄, 이동 구간, 집 자리 왕복을 모두
   둥글게 바꾼 뒤 점과 그 사이 선분(칸의 1/4 간격 표본)이 모두 키운 격자의 빈칸 위인지 본다.
7. **커버율.** 둥글게 바꾼 경로를 따라 청소 폭 안(경로에서 폭의 반 이하)에 중심이 든 칸을 센다.
   - HALL 바닥 기준: 키우기 전 HALL 바닥 칸(HALL 안, 진열대 밖. `keepout_extra`는 실제 바닥이라
     넣는다)으로 나눈다.
   - 청소 격자 기준: 키운 격자의 빈칸으로 나눈다. 벽 쪽 가장자리 띠는 나중에 FollowWall로 도는
     한 바퀴가 맡는다.
8. **한 바퀴 시간.** (줄 길이 합 + 둥글게 바꾼 이동 길이 합) / 0.12 m/s. 제자리 회전은 뺐다.

## 파라미터 (`Params`)

| 이름 | 기본값 | 뜻 |
|---|---|---|
| `grid_m` | 0.025 | 청소 격자 칸 크기 |
| `robot_radius_m` | 0.083 | 로봇 몸 원 반지름 |
| `margin_m` | 0.01 | 막힌 것을 키울 때 더하는 여유 |
| `line_spacing_m` | 0.10 | 줄 간격 상한(몸 폭 0.112 기준. 청소 폭 정의가 정해지면 바꾼다) |
| `clean_width_m` | 0.112 | 커버율을 셀 때 청소 폭(지금은 몸 폭) |
| `turn_radius_m` | 0.10 | pode_fsm 모서리 원호 반지름(`fleet_map.TURN_RADIUS_M`) |
| `speed_mps` | 0.12 | 한 바퀴 시간 계산 속도 |

## 결과 (기본 파라미터)

| | v7 | d2 |
|---|---|---|
| 셀 | 7 | 3 |
| 줄 | 16 | 9 |
| 줄 길이 합 | 8.775 m | 12.950 m |
| 이동 길이 합(둥글게 바꾼 뒤) | 3.879 m | 2.227 m |
| 한 바퀴 시간(회전 제외) | 105.5 s | 126.5 s |
| 커버율, HALL 바닥 기준 | 63.0 % | 82.5 % |
| 커버율, 청소 격자 기준 | 100 % | 100 % |
| P-1을 가까운 빈칸으로 옮김 | 예: (0.12, 0.10) → (0.113, 0.263) | 아니오 |
| HALL 바닥 칸 / 청소 격자 빈칸 | 2353 / 1004 | 2489 / 1663 |

- v7의 P-1은 칸막이 1 둘레 `keepout_extra`([0.19, 0, 0.31, 0.20])를 0.093 키운 띠와 남쪽 벽 띠
  안이라 막힌다. 가장 가까운 빈칸은 0.16 m 북쪽이다.
- v7의 HALL 바닥 기준이 낮은 까닭: 충전 칸 둘레 `keepout_extra`, OUT_DOCK과 WORK_DOCK 둘레,
  진열대 셋 둘레, 벽 띠를 모두 0.093 키우면 HALL 바닥 2353칸 중 1004칸만 남는다. 남는 부분은 벽 띠와
  함께 FollowWall 한 바퀴와 다음 단계에서 정한다.
- 줄 간격 0.068(실제 0.05 m): v7 24줄, 줄 14.100 m, 이동 4.361 m, 153.8 s / d2 14줄, 줄 21.700 m,
  이동 3.508 m, 210.1 s. 둥근 경로 검사는 둘 다 통과한다.

결과 파일: `pc/fleet_core/fleet_core/data/coverage_v7.yaml`, `coverage_d2.yaml`. 파라미터, 집 자리,
요약, 셀(칸 중심 기준 상자, 줄 수), 줄(시작점, 끝점, 셀), 이동 구간(꺾은선 점, 길이)을 담는다.
좌표는 mm로 반올림했다. 이동 구간은 둥글게 바꾸기 전 꺾은선이고 그 길이도 둥글게 바꾸기 전 값이다.
요약의 이동 길이는 둥글게 바꾼 뒤 값이다.

## 다시 만들기

```bash
cd pc/fleet_core
python3 -m fleet_core.coverage --layout v7 --write
python3 -m fleet_core.coverage --layout d2 --write
python3 -m fleet_core.coverage --layout v7 --line-spacing 0.068   # 쓰지 않고 요약만
```

시험: `cd pc/fleet_core && ROS_DOMAIN_ID=89 python3 -m pytest -q test/test_coverage.py -p no:cacheprovider`
(data 파일 일치, 둥근 경로 빈칸 검사, pode_fsm `rounded`와 같은 점, 청소 격자 기준 커버율 90 % 이상,
줄 간격 0.068에서 검사 통과).

## Fields2Cover와 opennav_coverage를 쓰지 않은 까닭

- **Fields2Cover**는 넓은 농경지용이다. 헤드랜드, 큰 회전 반경, 필드 경계 다각형을 전제로 줄과
  회전 경로를 만든다. 2 m × 0.8 m HALL의 0.10 m 줄에는 과하다. PC에 GDAL, OR-tools, boost 의존성이
  들어온다.
- **opennav_coverage**는 Fields2Cover를 감싼 Nav2 서버다. 같은 의존성이 들고, 청소 영역을 다각형으로
  따로 넘겨야 한다.
- 대신 HALL은 사각형들의 합이고 지도 정보(구역, 진열대, keepout_extra, 지점)가 이미 fleet_core에
  있다. numpy만으로 같은 입력에서 늘 같은 결과를 내고, pode_fsm이 실제로 보내는 둥근 경로로 바로
  검사할 수 있다.
