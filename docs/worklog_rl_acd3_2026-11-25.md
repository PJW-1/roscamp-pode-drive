# 작업 기록: RL acd3 밤 학습 (2026-11-25)

acd2(`acd24/t_acd_s3_c2/model_1496.pt`, 레시피 a+c+d, seed 3)에서 이어 학습해 다음 후보를 고른다. 결과와 결론은
`docs/report_2026-11-25_rl_acd3.md`에 둔다. 이 문서는 무엇을 왜 돌렸고, 결과를 보기 전에 정한 고르는 기준이 무엇인지 적는다.

## 1. 왜 다시 학습하나

- **지도.** acd2는 진열대 A와 남쪽 서쪽 진열대의 서쪽 끝이 서로 바뀐 v7 지도로 학습했다. main 8d106e5에서 바른 값
  (A 0.65, 남쪽 서쪽 0.70)으로 고쳤으므로 고친 지도에서 다시 학습하고 다시 평가한다.
- **몸 여유.** 11-24 Gazebo Q2→E-3에서 acd2의 판별 최솟값 몸 여유 중앙값이 3.3 cm로 4b(6.5 cm)보다 작았다.
- **lidar 배율.** 11-24 실측에서 pode2 lidar는 거리를 약 0.958배로 읽는다. 학습 관측은 참값이다.

## 2. 돌린 것

모두 acd2에서 이어 250번, 4096 env, seed 3, 레시피 a+c+d의 설정 그대로(`jobs_main.txt`, `jobs_lidar.txt`).

| 이름 | 바꾼 것 |
|---|---|
| t_map | 고친 v7 지도만 |
| t_wall | 벽·진열대 8 cm 안에 들면 벌점(`near_wall_m=0.08`, `w_near_wall=-0.2`) |
| t_lidar | 에피소드마다 lidar 거리 배율을 0.95~1.03에서 뽑아 관측에만 곱함(`lidar_scale_range`, 319ec95) |

평가는 모두 `play.py --episodes 1 --seed 7 --num_envs 4096`이라 같은 칸의 실행은 같은 에피소드를 env 번호로 짝짓는다.
칸은 0.12 m/s와 0.08 m/s의 random·head-on 넷, 그리고 lidar 배율 0.958 고정의 0.12 random 하나다. acd2도 고친 지도에서
같은 칸을 다시 평가한다. 표는 `docs/rl_acd3_2026-11-25/acd3_tables.py`로 만든다.

## 3. 고르는 기준 (결과를 보기 전에 정함, 02:20)

1. 점수는 다섯 칸(0.12 random, 0.12 head-on, 0.08 random, 0.08 head-on, 0.958 배율 0.12 random) 성공률의 평균이다.
   배율 칸을 넣는 까닭은 실물 lidar가 그렇게 읽기 때문이다.
2. 후보는 어느 칸에서도 acd2보다 2 SE 넘게 나쁘면(짝 차이가 음수이고 "outside") 고르지 않는다.
3. 남은 후보 가운데 점수가 가장 높은 것을 고른다. 점수 차가 1 %p 안이면 t_wall, t_lidar, t_map 순으로 고른다
   (Gazebo 몸 여유, 실물 lidar 대응이 학습의 목적이었으므로).
4. 1~3을 지나는 후보가 없으면 acd2를 그대로 두고, 고른 것 없이 보고한다.
5. 고른 후보는 `store_arena_acd3`로 내보내고 Gazebo에서 4b, acd2와 견준다(Q2→E-3, c_moving, 칸마다 20판, shim으로 감쌈).
   Gazebo 결과는 실물 후보를 정할 때의 근거이고, 위 고르기를 뒤집지 않는다. 실물에 올릴지는 사용자가 정한다.

## 4. 진행

- 01:19 큐 시작. 01:53 t_map 끝(1961 s). 학습 중 마지막 20번 평균 성공 0.752(acd2 마지막 조각 0.744, 옛 지도).
- 큐 두 개(main, lidar)는 원래 차례로 돌리려 했으나, 기다리는 스크립트가 main 큐 프로세스를 잠깐 못 보고 01:42에
  lidar 큐를 일찍 띄웠다. 두 큐는 같은 잠금으로 한 번에 하나씩만 돌린다. 평가는 학습이 끝난 뒤에만 체크포인트를 고르므로
  (`eval:<tag>`는 같은 큐에서 그 학습 뒤에 있거나, 다른 큐에서 잠금을 기다린 학습 뒤에 있음) 섞여 돌아도 결과는 같다.
- lidar 목록을 도는 큐가 둘이 되어 t_lidar와 lidar 평가 여덟 개가 두 번씩 돌았다. 결과는 유효하고, `queue.sh`를 고쳤다(보고서 6절).
- 06:55에 큐의 작업 25개(smoke 둘, 학습 셋, 평가 스물)가 끝났다. 정한 순서대로 t_wall을 골라 `store_arena_acd3`로 내보냈고, 06:59~08:24에 Gazebo 비교를 돌렸다. 결과는 `docs/report_2026-11-25_rl_acd3.md`에 있다.
